# qq-agent 市场插件移植评估

> 2026-10-10 调研产出。来源：kondius.cn 插件市场（182 插件 / 133 技能 / 90 人设）。
> 已下载 11 个插件源码 → `D:\agent-workspace\research\qq-agent\_market\dl\`（另有 deai-flavor 技能）。
> 目的：评估"机制最巧"的插件如何移植到 dd19-bot。
> 状态：**评估完成，待挑选实施**。

## 一览（按移植优先级排序）

## 详细评估

### 1. DSML 工具调用兜底 ⭐⭐⭐（最高）

**机制**（dsml-parser.js 214 行 + index 66 行）：
- 快速否决 `looksLikeDsml`（`/DSML/i`）→ 宽松正则解析：
  - 竖线 1~2 个、全角（｜）半角（|）混用（`PIPE = '[\uFF5C|]\s*[\uFF5C|]*'`）
  - 标签名按 `_` 切词、词间允许 `[\s_]*`（容忍 `tool calls`/`toolcalls`）
  - `invoke`/`parameter` 带属性解析（单双引号都认）
- **类型还原** `coerceValue`：`string="true"` 常标错——能 JSON 解析的（数字/布尔/数组）就还原
- **铁律**：认不出来返回空数组，绝不抛错、绝不猜（防造出错误的工具调用）
- 工具名白名单 `^[A-Za-z0-9_.-]{1,64}$`

**我们的现状**：`core/textnorm.py` 的 `looks_like_tool_leak` 命中后——handler 条目跳过 + 正文拦截（发群前拦）——**只丢弃、不抢救**（当时用户选定策略）。

**移植方案**：
1. 新增 `core/dsml.py`（Python 版解析器，逻辑照搬：宽松正则+类型还原+白名单）
2. 在 `llm_chat` 的正文处理处：`looks_like_tool_leak` 命中 → **先尝试解析**：
   - 解析出 `send_message`（args.messages）→ 走 `_direct_send` 正常发送（受 `_SEND_MAX_ITEMS`/去重/防重窗口约束）
   - 解析出 `send_reaction` → 执行 reaction
   - 解析出其它工具 → 忽略（模型下轮可再调；只救"用户可感知"的发送）
   - 解析失败/空 → 维持现状（拦截丢弃 + "卡了一下"）
3. 测试：真实 DSML 样本（含双竖线偏差版）逐条断言

**风险**：解析错误把内心戏发出去——用"只救 send 类 + 保守解析 + 发送层去重"兜底。

### 2. 投递即收尾（提前结束）⭐⭐⭐

**机制**（reply-guard/policy.js + 市场"token 直接减半/投递即收尾"同款）：
- 判定：本批**有 send_message 且实际发出** + **无工具失败** + 无预告（"我去看看/等下告诉你"）+ 无未兑现承诺（说要发图没发）→ 跳过收尾轮
- 原则：**宁可少省一轮，不能打断做事**

**我们的现状**：`chat_once` 循环 `range(llm_tool_max_rounds + 1)`——最后一轮 `force_final`（不带工具逼出最终回答）。协议模式下发完话后这轮正文=思考（不发群、被丢弃）——**纯烧 token**（每轮重发全量上下文）。

**移植方案**：
- 在 `chat_once` 循环内：工具轮结束后，若 `is_replied()` 为 True **且** 本批无失败 **且** 发出的文本无预告/承诺模式 → `break`（直接返回当前 completion，不再进 force_final 轮）
- 需要：handler 返回结构化（isError 标志）——现在只返回文本，改造点小
- 预告/承诺正则可直接借用 policy.js 的两条（PREVIEW / PROMISE_ASSET 中译版）
- **开关**：`EARLY_FINISH_ENABLED=1`，可回退

### 3. 拦截+理由回传 ⭐⭐

**机制**（reply-guard/guard.js 231 行）：
- 发送前检查 send_message 参数，命中即**打回**——**并把改写理由回给模型**（"这句话在解说你的打字过程，去掉它直接说想说的"）
- 检查项：解说打字过程 / 催睡超限（一晚默认 1 次）/ **每条差不多长**（≥3 条最短≥16 字，或 ≥2 条最短≥24 字——"匀速输出感"）/ 比喻（仿佛/宛如/跟…似的）/ 硬语气（词表+句式）/ 看图说话
- 与"静默跳过"的本质区别：**模型知道为什么被打回，会换个说法重发**——用户可感知质量↑

**我们的现状**：`_is_recent_repeat`（60s 同文≥8字跳过）等拦截是**静默**的；`_CHAT_RULES` 里对应内容是软约束。

**移植方案**：
- 把 `_is_recent_repeat` 从"静默跳过"改为"返回理由给模型"（"这句刚发过了，换个说法或安静结束"）
- 新增"字数均匀检测"（hitsEvenLength 直接可移植）——我们 `_SEND_MAX_ITEMS=3` 场景完全适配
- 催睡类词表（我们的"AI 味黑名单"里有相关内容，可硬化为代码）
- 全部做成"拦截器返回 (block, reason)"的统一小框架

### 4. 沉默审计 ⭐⭐

**机制**（reply-audit）：运行结束"既没 finish 也没发消息"时——**另起一次独立模型调用**（极短系统提示，只判断 SAY/QUIET；只看思考，裁剪头 1/4+尾 3/4）——SAY 时本地模板拼提醒注入下一轮。保守（拿不准 QUIET——误判=内心戏补发进群）。一次运行只审一次。

**我们的现状**：无。协议下"安静结束"可能掩盖"想说没发"（模型忘了调 send_message）。

**移植方案**：
- `chat_once` 结束后（本轮无任何发送）：可选起一次审计调用（复用 `budget` 记账；小模型或同模型短 prompt）
- 判定 SAY → 在下一轮 system/user 尾部注入提醒（"你上一轮写了要发给群友的话但没有发出去"）
- **成本**：一次额外调用——做成开关 `SILENCE_AUDIT_ENABLED`（默认关）

### 5. per-sender 跟聊窗口 ⭐⭐

**机制**（short-followup 110 行）：`replied()` 在 send_message/send_sticker **成功后**开窗口（key=(群,人)，默认 5 分钟）；窗口内该人再发消息（非 @、有实质内容）→ 继续接。**after-tool 钩子**判断"回的是谁"（atUserId/replyTo/默认最后一条）。窗口内注入"【短期跟聊】无需再次艾特，自然接着回答"。

**我们的现状**：`auto_chat` 的 `_CONTINUATION_WINDOW=120s`——**全局窗口**（机器人说过话后该群继续接），不区分人。

**移植方案**：
- 窗口 key 从群改为 **(群, 人)**：机器人回复了谁 → 谁进窗口（回复对象的识别：@谁 / 引用谁 / 触发消息发送者）
- 效果：更精确（不会因别人插话误触发），也不会漏（跟谁聊就接着跟谁）
- 改动集中在 `auto_chat` 的窗口逻辑，小

### 6. 正文抢救（reply-safety 路径A）⭐

**机制**：模型没调工具、话写在正文 → 四级递进：①计划腔否决（正则）②loose-send 正则抽取（不花模型调用）③裁判级（另调模型判"成品 vs 内心戏"）④草稿溯源（只保留确实出自已记录草稿、没发过的原句）。铁律：只搬原句、拿不准一律沉默。**判定方向刻意激进**（误判代价=少发一句 vs 安静，安全）。

**我们的现状**：正文=丢弃。**与 #1 DSML 场景重叠**（DSML 解析成功后其实已覆盖"正文里的成品"一大类）。

**移植方案**：做 ①②级（正则，零成本）；③④暂不做（额外模型调用+复杂）。与 DSML 解析合并为一个"正文处置管线"：DSML 解析 → 正则抢救 → 都没有则安静结束。

### 7. 内心生活（inner-life）⭐

**机制**：`mind_note` 记 mood（≤20字）+ topics（挂心事≤3条）；TTL（12h/24h）+容量上限；**近重复合并**（归一化后相等，或短句≥6字且占长句≥50%）；**过期口径="最近一次触碰"**（注入不续期，主动重记才续）；每轮注入【你此刻的心绪】（无则不注入）。

**我们的现状**：mood_loop 有心情（对群/对人），无"挂心事"概念。

**移植方案**：给 mood 系统加 `topics` 表（或复用 mood 存储）——"还没想完的事"（等一个快递、想说没说的话）；注入到动态块；`mind_settle` 对应"想通了清掉"。**注意**我们已有记忆/心情，注意别重复注入。

### 8. 群文化记忆（group-learner）⭐

**机制**：每次被触发回复时把近期群聊批量喂给"记忆整理模型"→提炼/合并进"群文化"（黑话/烂梗/话题/氛围/人物关系/称呼）；按**人设指纹分槽**（sha1）；每回复只注入一小段（百来字）；后台 setImmediate 不阻塞；计数+冷却触发。

**我们的现状**：jargon_loop（黑话表，手工/半自动）+ memory（对群友印象）——缺"群整体画像"。

**移植方案**：中等工程——（a）提炼管线（复用现有记忆模型调用机制）；（b）存储（群文化表）；（c）注入（动态块）。**收益**：越攒越像本群人。工作量中-大，建议独立评估。

### 9. 生活事件（life-memory）⭐

**机制**：`life_note` 记事件（小事 24h 淡忘；`ongoing=true` 的大事 168h 记到 `life_done`）；近重复续期；注入极短。

**我们的现状**：无。**前提**：人设要有"自己的生活线"（十九作战卡目前没有生活设定——要做这个得先给人设补生活背景）。

**移植方案**：小工程（一张表+两个工具+注入），**但价值取决于要不要给十九/ Elena 写生活线**。可选。

### 10. 缓存重排（cache-stability）☆

**机制**：before-llm-messages 重排 user 内容——【记忆】【表情包】等易变块挪到【已读/未读信息】之后；system 末尾钉稳定规则（视频理解说明）。

**我们的现状**：**已做大半**——system 稳定（人设+规则）+ 动态块拼 user 尾部（"前缀缓存命中率最大化"已在注释里）。仅剩 user 内部顺序微调空间。

**移植方案**：检查 user 内【记忆】（每轮变化）与【历史消息】（累积增长）的顺序——确保易变块靠后。小优化，随手可做。

### 11. 反侦察（anti-recon）☆

**机制**：before-tool 硬拦 send_message 内容：厂商自曝（deepseek）/承认 AI/元信息（提示词）/专属关系（"就你一个"）/制作者/项目名（NapCat/OneBot）；"主人"仅在群聊拦（否定语境放行——"什么主人我又不是狗"必须放行）。

**我们的现状**：人设软约束（"不解释模型/提示词"）+ 我们走**"温和承认"路线**（"嗯，是啊。不过跟你聊天的时候，我是认真的。"——用户选定）。

**移植方案**：与我们的路线部分冲突（不拦"承认是机器人"）——可选移植：**元信息**（提示词/项目名/厂商名）硬拦 + 群聊"主人"（我们没这概念，跳过）。低优先。

## 建议批次

- **批1（高价值小步）**：#2 投递即收尾 + #3 拦截理由回传 + #5 per-sender 窗口 —— 都是小改动、立竿见影（省 token / 体验提升）
- **批2（核心痛点）**：#1 DSML 抢救（+#6 正则级正文抢救合并）—— 直接消灭"卡了一下"体验
- **批3（可选增强）**：#7 挂心事 + #10 缓存微调 + #4 沉默审计（开关默认关）
- **批4（大工程）**：#8 群文化记忆（独立评估）；#9 生活事件（先决定要不要生活线）
